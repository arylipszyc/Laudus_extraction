## Diagnóstico estrella — el descuadre NO era del modelo, era corrupción de datos

El piloto daba `TC:Real = +2.545.013` en vez de −3.219.948 (cierre abril). Diagnostiqué:
**categorizar una compra TC borraba la pata `Liabilities:TC:Real`.** `_rewrite_file` decidía qué
pata preservar resolviendo `bank_account_id` → daba el gasto lump `430005`, NO la deuda `TC:Real`
(que es cuenta derivada por nombre, sin bank_account_id). Como ninguna pata era 430005, reescribía
LAS DOS a la cuenta de gasto → se anulaban → deuda borrada. feb (12) + mar (25) categorizadas =
destruidas; abril intacta (sin categorizar). El pago no se categoriza → su pata sobrevivía → saldo
positivo. Artefacto: `valentina-bug-categorizacion-destruye-tc-real-2026-07-02.md`.

**Fix del dev (Moishe no está, lo tomó el dev principal):** `_rewrite_file` reescribe SOLO la pata
`Expenses:`/`Income:`, preserva SIEMPRE `Assets:`/`Liabilities:`. Re-importé feb/mar/abr sanas →
`TC:Real == −3.219.948` EXACTO, 66 compras, 0 destruidas. Cadena contigua confirmada (apertura de
cada cartola == cierre de la anterior).

## Cómo Laudus registra el pago de la TC (clave para el cuadre)

UN asiento por mes: `Assets:Banco → Expenses:...TC:<lump>-430005`, glosa "Visa BCI 1027 EAG <mes−1>"
(corrida un mes). El monto == el PAGO PAC de la cartola exacto (feb 4.757.783 / mar 3.724.232 /
abr 2.054.314). Ese es el asiento a mostrar/cuadrar. Se identifica: toca 430005 y NO es cartola-tc.
