## Deferred from: code review of E1-0-scaffold-pipeline-migracion (2026-07-24)

- **[Smoke Tier B] El smoke escribe el stub en la carpeta de addons compartida del spike** — `pipeline/odoo_migration/tests/test_odoo_smoke.py`. El compose del spike monta `./addons:/mnt/extra-addons` (bind mount), así que `odoo scaffold x_laudus_smoke /mnt/extra-addons` escribe en `_spike-odoo/addons/x_laudus_smoke` (dir compartido con el stack del spike), y en Linux los archivos root-owned harían fallar el `shutil.rmtree` de teardown (tragado por `ignore_errors=True`) dejando residuo. ## Deferred from: code review of E1-2-transformador-colapso-verificador-paridad (2026-07-25)

- **[Parity] Exclusiones por CONTEO, no por identidad** — `pipeline/odoo_migration/parity.py` (`verify_counts`/`run_tier_a`, `expected_excluded_*`). Un `int` acepta la exclusión de *cualesquiera* N moves: si E1.3 excluye el par equivocado que también netea a 0 por `(company, code, currency)` (la firma de cualquier wash), origen+destino+conteos quedan verdes habiendo borrado historia real. **Razón del defer:** la API por conteo es la que pinneó la story E1.2; subirla a identidad (set de `je_id` excluidos + verificar que esos y solo esos faltan y que netean a 0) corresponde a **E1.3**, que es quien implementa los washes con log auditable — el consumidor real de la API.
- **[Transform] `OdooLineRecord` no conserva `posting.price`** — `pipeline/odoo_migration/transform.py`. La pata `100 USD @ 800 CLP` del golden guarda solo `(USD, 100)`; E1.5 necesita el contravalor para `amount_currency`/debit-credit en moneda compañía. **Razón del defer:** la story E1.2 asigna explícitamente el precio a **E1.5** ("dato para E1.5, no para la paridad Tier A"); los records se regeneran in-process desde el mirror, así que no hay pérdida de información entre stories — E1.5 agrega el campo cuando lo consuma.
- **[Parity] `ParityError` sin diffs programáticos** — `pipeline/odoo_migration/parity.py` (`run_tier_a` trunca el mensaje a 5 reprs; los diffs completos no viajan como atributo de la excepción). En un descuadre real de cientos de códigos el operador no puede recuperar la lista completa. **Razón del defer:** DX de diagnóstico, no correctitud; resolver cuando el verificador corra a escala (**E1.3/E1.6**) adjuntando `origin_diffs`/`destination_diffs` a la excepción.
- **[Mapping] Consistencia `(company, odoo_account) → otype` no validada** — `pipeline/odoo_migration/mapping.py`. Dos códigos que colapsan al mismo destino con `otype` distinto pasarían el load sin error y E1.5 crearía la cuenta con tipo ambiguo. Hoy 0 conflictos en la tabla versionada (verificado). **Razón del defer:** el consumidor del `otype` es **E1.5** (quien crea el chart); validar ahí o al endurecer el loader para esa story.
